OpenShell Architecture: Gateway, Supervisor, Sandbox

CLI / SDK / TUI

→

  • Gateway: owns sandbox lifecycle, policy revisions, credential storage, session records, relay coordination. One Gateway → many sandboxes
  • Supervisor: starts before agent, fetches policy, prepares isolation, launches agent as unprivileged child. Owns filesystem, process, network, credential enforcement
  • Static policy (locked at creation): filesystem_policy, landlock mode, process UID/GID — agent cannot modify
  • Dynamic policy (hot-reloadable): network_policies per binary, network_middlewares for HTTP/GraphQL/MCP traffic inspection
  • Compute drivers: Docker, Podman, Kubernetes (SIG Apps agent-sandbox), MicroVM
  • All policy decisions logged in OCSF audit trail — blocked requests return descriptive errors
Security

Five Layers of Kernel-Enforced Isolation

1

Landlock LSM

/usr, /lib, /etc read-only. /sandbox, /tmp read-write. Everything else denied. hard_requirement mode fails startup if any path gap.

2

Seccomp BPF

Blocks mount, pivot_root, bpf, kexec, raw sockets. No kernel modules, no namespace escape. Kernel 3.17+.

3

Network Proxy

All egress via CONNECT proxy. Binary ID by SHA-256. OPA/Rego per destination. Can inspect MCP traffic: allow query, block write.

4

Credential Isolation

Keys stored at Gateway, injected at runtime as env vars. Never on sandbox filesystem. Driver vars override templates.

5

Signed Images

Konflux-built UBI9. FIPS, SBOM, RPM locks. OpenCode, Codex, Goose, OpenClaw, Pi at quay.io/aipcc/.

  • Container isolation stops workload-to-workload attacks — OpenShell stops agent-to-world attacks
  • Supervisor can inspect HTTP, GraphQL, and MCP traffic — allow data query, block write through same API
  • Default posture: deny-all — you explicitly grant what the agent needs
Infrastructure

The Inference Engine: llm-d + EPP Prefix-Cache Routing

  • LLMInferenceService: single CR declares model + replicas + GPU → RHOAI creates vLLM, Gateway, EPP
  • EPP (Envoy ext-proc): Filter → Score → Pick pipeline per request
  • prefix-cache-scorer (weight 3): routes to replica with warm KV cache. Precise mode: real-time KVEvents over ZMQ → global block-to-pod index → exact token-ID prefix matching
  • queue-depth-scorer (weight 2): avoid overloaded replicas
  • kv-util-scorer (weight 2): balance GPU memory pressure
  • 69% p90 TTFT reduction with prefix-cache routing under multi-turn load (AWS reference benchmark)
  • For MCP development: agent sends same file context repeatedly as it iterates — warm cache drops prefill to <20ms
CNCF Sandbox project. InferencePool GA. vLLM publishes KVEvents, EPP's KV-Cache Indexer maintains global state. Token IDs via vLLM render sidecar.
Infrastructure

MaaS Governance: API Keys, Rate Limits, Access Control

  • MaaSModelRef: model registered and ready. HTTPRoute configured, inference can flow
  • MaaSAuthPolicy: controls WHO — maps OpenShift groups to model access. Missing → 403 Forbidden
  • MaaSSubscription: controls HOW MUCH — token rate limits via TokenRateLimitPolicy (e.g. 100K tokens/24h). Missing → 429 Too Many Requests
  • Both required — subscription without auth = billing leak; auth without subscription = unbounded cost
  • API keys: sk-oai-* prefix, SHA-256 hashed in PostgreSQL, bound to one subscription
  • Create via POST /maas-api/v1/api-keys (OpenShift token auth). Custom expiration: 90d, 30d, 1h
  • Per-key revocation without affecting other keys. Security incident → revoke all, re-mint
  • Bursty agent workloads (30 rapid tool calls) are fine — rate limit is per-subscription token budget, not per-request

Governance

Enterprise MCP Governance for Regulated Industries

  • Tool-Level RBAC: not all developers see all tools. “fetch_customer_data” → read for support. “submit_compliance_report” → compliance officers only. Enforce at gateway, not in system prompt
  • Structured Audit Logging: tamper-evident JSON per invocation — caller ID, agent session, tool, redacted args, policy decision, latency, correlation ID. HIPAA: 6yr retain. Financial: 7yr. Pipe to SIEM in OCSF format
  • PII Redaction: in-flight at MCP gateway — Luhn-verified card masking, SSN, email, AWS keys, JWTs, PATs. Regex-extensible. Before tool responses reach the LLM
  • Human-in-the-Loop Gates: irreversible actions → status=‘pending_review’. Segregation of duties: builder ≠ approver. SOX 404, SOC 2 Trust Criteria
  • Typed Error Envelopes: structured error codes, user-facing message, correlation ID — no stack traces with connection strings leaking to the LLM
Patterns from: Forrester AEGIS Framework, MCP Enterprise Architecture (closegate, enterprise-mcp-gateway), SOC 2 / DORA / FINRA audit guides.

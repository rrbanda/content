Solution Architecture

Three horizontal bands — control, execution, platform — with the MCP Gateway as the checkpoint between them. Every component is a role that several implementations can fill.

Concrete example — 5G Core Health Agent

A network health agent demonstrates the three nouns that the architecture keeps separate:

  • Skill (instruction file) — a triage runbook telling the agent when and how to call tools. Loaded by the harness. No compute of its own.
  • MCP server (tool endpoint) — a Data-Mesh-Map Builder that advertises schemas for correlating logs, traces, and metrics per CNF. This is what the MCP Gateway fronts and claims-checks.
  • Service backend (compute) — the actual query engine, running on GPU or CPU, that the MCP server sits in front of. Three things, three lifecycles, three enforcement points.

Skill (instruction file)

Instruction files and schema bindings loaded by the harness. A skill tells the agent what to call and when. No compute of its own — progressive disclosure lives here.

MCP server (tool)

A callable endpoint in a separate process with an advertised schema. This is the only thing the MCP Gateway fronts and claims-checks. One MCP server can wrap one or many backends.

Service backend (compute)

The actual compute the MCP server sits in front of. Optimization on GPU, DataFrames on CPU, a KServe endpoint, or a Slurm job. Swapping a backend is an endpoint change, not a redesign.

MCP Gateway (checkpoint)

Fronts every backend the model selects at runtime. Backends the platform invokes on the agent's behalf (inference, batch jobs) carry their own admission control. All paths land in the same trace.

Defense in Depth: Three Isolation Rings

Each ring assumes the ring inside it has already been compromised. Four cross-cutting controls apply across all three. The rings limit what a compromised agent can do; the controls reduce the chance it gets compromised.

Ring 1 — Process

OpenShell supervisor enforces per-binary, per-path, per-endpoint policy via seccomp, Landlock, and network namespaces. Irreversible after process start — the agent cannot override it.

Ring 2 — Pod

Kubernetes pod security standards, SELinux, NetworkPolicy, and resource quotas bound what the pod can reach. Optionally, Kata Containers add a dedicated microVM kernel per sandbox pod.

Ring 3 — Hardware

Confidential containers extend the trust boundary into silicon. Hardware attestation verifies the sandbox runs the code it claims before any secret is released.

Inference Routing & Skill Placement

An inference request crosses three routers because the three decisions have different owners. The MCP Gateway fronts every backend the model selects at runtime. Backends the platform invokes under pre-authorized policy carry their own admission control. All paths land in the same trace.

Tier 1 — Security

Lives client-side in every sandbox, inside the supervisor. Confidential context never leaves the cluster. Anything routed externally is PII-masked first.

Tier 2 — Cost

A lightweight classifier selects the cheapest model that can handle the request. Adds latency and can misroute — needs a fallback that escalates on low confidence.

Tier 3 — Efficiency

Once the model pool is fixed, llm-d endpoint picker maximizes KV-cache hits and balances load across vLLM workers.

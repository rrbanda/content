Architecture

llm-d: Kubernetes-Native Distributed LLM Inference

  • CNCF Sandbox project — co-created by Red Hat, Google Cloud, IBM Research, CoreWeave, NVIDIA
  • LLMInferenceService CRD declares model, replicas, GPU resources → RHOAI creates vLLM pods, Gateway, HTTPRoute, InferencePool, and EPP automatically
  • EPP (Endpoint Picker Plugin) scores every replica on three dimensions — does NOT round-robin
  • Prefix-cache-aware routing: sequential agent requests hit the replica with warm context → skip prefill entirely
  • Native activation: scheduler: {} on the LLMInferenceService → RHOAI creates EPP natively, no manual deployment
  • GA in Red Hat OpenShift AI since version 3.3
For coding agents, prefix-cache routing is the highest-impact optimization: subsequent requests in a chain reuse cached context, reducing prefill from hundreds of milliseconds to <20ms.
Architecture

EPP Scoring: How Requests Hit the Right GPU

Prefix Cache Scorer

Weight 3

Does this replica have the prompt prefix cached? Routes agent chains to the same replica — skips prefill entirely.

Queue Depth Scorer

Weight 2

How many requests are queued? Prevents hotspotting even when cache affinity is high.

KV-Cache Utilization

Weight 2

How full is the replica’s KV-cache? Avoids routing to replicas near eviction threshold.

  • Composite score = (prefix × 3) + (queue × 2) + (kv_util × 2) — highest score wins
  • InferencePool discovers replicas via label selector: kserve.io/component: workload
  • Scoring happens in sub-millisecond — negligible overhead vs. prefill savings
Governance

MaaS: Models as a Service Governance

Governed Access
  • sk-oai API keys per developer or team
  • MaaSSubscription with token rate limits and model entitlements
  • MaaSAuthPolicy enforces authentication at the gateway
  • Audit trail: subscription ID, model, tokens, timestamp on every request
  • 401 without key — no unauthenticated path to the model
Ungoverned Access
  • Direct vLLM endpoint, no authentication
  • No rate limits — one user can consume all GPU capacity
  • No audit trail — impossible to attribute usage
  • No model access policies — every model exposed to every user
  • No revocation — no way to cut off a compromised client

Developer Experience

OpenShift DevSpaces: AI-Powered IDE Per Developer

  • Cloud-hosted VS Code in a dedicated Kubernetes namespace per developer
  • OpenCode pre-installed: agentic coding tool that reads files, writes code, runs commands, iterates
  • MaaS endpoint pre-configured: developer opens the IDE and AI assistance is immediately available
  • API key injected as a Secret: no manual configuration, no “enter your API key” dialog
  • Source code stays in-cluster: browser sends keystrokes, receives rendered HTML — no source code transits the network boundary
  • Declarative onboarding: DevWorkspace CR → 60 seconds → hand them a URL
  • Also supports Continue and Roo Code (formerly Cline) for teams with existing preferences
DevWorkspace CRD is versionable, templatable, auditable. New developer onboarding is a Helm release, not a ServiceNow ticket.

Risk Assessment

Cloud AI vs. Self-Hosted: The Risk Calculus

Cloud-Hosted AI Coding
  • Source code transits external infrastructure for inference
  • Limited visibility into data handling, caching, retention
  • PCI-DSS scope expands to include third-party AI vendor
  • Compliance team must audit vendor infrastructure
  • Data residency uncertain — inference may cross regions
Self-Hosted (This Architecture)
  • Source code never leaves the cluster
  • Full visibility — you own every component
  • PCI-DSS scope unchanged — no data crosses the perimeter
  • Compliance team audits your own infrastructure
  • Data residency guaranteed — your DC, your VPC
Compliance

Compliance Architecture: Four Design Choices

  • Air-gapped deployment: entire stack deployable via mirror registries and OCI artifacts — no internet connectivity post-deployment
  • FIPS 140-2 / 140-3: RHEL validated cryptographic modules for all TLS, encryption, and certificate operations — OS-level, not application-level
  • Three-layer audit trail: MaaS logs (API requests) + TrustyAI logs (blocked prompts) + OpenShift audit logs (K8s API calls)
  • Zero data egress: DevSpaces in-cluster, inference in-cluster, model weights on PVCs — browser traffic carries rendered HTML, not source code
  • Namespace isolation: per-developer RBAC, NetworkPolicy, resource quotas — K8s-native multi-tenancy enforced at the API server
ROSA on GovCloud has FedRAMP High Authorization. ARO supports Azure Government regions. On-premises deployments run on RHEL with FIPS mode enabled cluster-wide.
